# 读懂项目

按「先全局、再局部」的顺序来，读到能回答用户的问题为止，不必读完所有文件。

## 1. 先看说明与配置

- README、AGENTS.md / CLAUDE.md / HENG.md 等项目说明、CONTRIBUTING、docs 目录；
- 依赖与构建配置：`package.json`、`pyproject.toml`、`pom.xml`、`build.gradle`、`go.mod`、`Cargo.toml`、`Makefile`、
  `Dockerfile`、CI 配置——从这里能看出语言、框架、怎么装依赖、怎么构建、怎么跑测试。

## 2. 看目录结构

列出顶层目录与主要子目录，判断各自的职责（源码、测试、配置、脚本、文档、前端、后端……）。
大项目先找「分层」：接口层、业务层、数据层，或者前后端、多个子模块之间的边界。

## 3. 找入口，顺着关键流程读

- 入口：命令行程序的 main、Web 服务的启动文件与路由、前端的路由与页面、定时任务的注册处；
- 挑一两个最核心的流程（如「用户下单」「处理一个请求」），从入口顺着调用一路读到数据落地，弄清经过哪些模块；
- 读的时候记下关键的类型 / 数据结构，以及模块之间怎么传数据。

## 4. 验证理解

能跑就实际跑一下（装依赖、启动、跑测试），比只读代码更可靠；跑不起来的原因本身也是重要信息。

## 5. 向用户交代

用几段话说清楚：

- 项目是做什么的、用了什么技术；
- 怎么装、怎么跑、怎么测（确切的命令）；
- 目录与模块的分工，一两个关键流程是怎么走的；
- 读的过程中发现的值得注意的地方（奇怪的约定、明显的坑、过时的文档）。

用户想长期保存这些结论的，建议运行 `/init`，生成给以后的会话看的 AGENTS.md。
