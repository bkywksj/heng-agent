# 00 总体设计

> 2026-10-26。heng-agent 是类似 Claude Code 的终端编码智能体，独立于 heng 模型仓库，只通过 HTTP 接入模型。

## 1. 交付物

一个可安装的终端程序 `heng-agent`：在任意项目目录下运行，用中文派活，它读代码、改代码、跑命令，直到任务完成。
改文件、跑命令前先征得同意；会话自动保存，可续聊；项目根目录的 `HENG.md` 是项目记忆，每次自动读入。

## 2. 分层

```
cli          入口：参数解析，交互模式 / -p 非交互模式
ui           终端界面：输入框、流式渲染、斜杠命令、权限确认对话
agent        对话循环：发给模型 → 收到工具调用 → 执行 → 结果喂回，直到模型不再调工具
tools | context | session | permissions
model        模型客户端：Anthropic Messages 协议，SSE 流式解析
core         数据类型（消息、内容块、事件）、配置、错误
```

`agent` 通过两个回调和外界打交道：`on_event`（把文字增量、工具调用、工具结果交给界面显示）、
`approve`（需要确认时问用户）。所以同一个循环能接交互界面、非交互模式与测试。

## 3. 模型接入

- **两种协议**：Anthropic Messages（`{base_url}/v1/messages`）与 OpenAI Chat Completions（`{base_url}/chat/completions`），
  都用流式。循环里的消息一律是 Anthropic 格式，走 OpenAI 协议时发送前转换（tool_result → role=tool 消息，
  tool_use → tool_calls），流里的工具参数分片按 index 累积。两种协议的事件都归一成文字增量、完整工具调用、结束。
- **服务商配置档**（`model/providers.py`，与智码的 API Profile 同一思路）：协议 + 地址 + 模型名 + 密钥来源 + 密钥请求头方式。
  内置预设 heng、anthropic、deepseek、kimi、glm、qwen、openai、openrouter、ollama；用户在 `~/.heng-agent/config.json`
  里加中转站、改默认、改模型名，可用 `preset` 继承预设只写差异。`--provider` 选择，界面里 `/provider` 随时切换。
- **密钥请求头**：Anthropic 官方与 DeepSeek 认 `x-api-key`，Kimi、GLM 与 OpenAI 系认 `Authorization: Bearer`；
  `auth: auto`（默认）两个都带，中转站报 401 时可固定一种。
- **密钥来源**：环境变量（`api_key_env`，推荐）或用户配置文件（`api_key`）。只在请求头里用，不进会话、日志、报错；
  `--list-providers` 只显示是否已设置。
- **不做 Claude 订阅账号登录（OAuth）**：Anthropic 条款只允许订阅凭据用在其自有客户端，第三方使用有封号风险。
- `heng` 预设指向本机 `heng serve`：自己训练的模型，或 `proxy-claude.yaml` 转发到 Claude。

## 4. 工具（共 8 个）

| 工具 | 作用 | 权限类别 |
|---|---|---|
| `read_file` | 读文件，带行号，可指定起始行与行数 | read |
| `glob` | 按通配找文件（跳过 `.git`、`.venv`、`node_modules` 等） | read |
| `grep` | 按正则搜内容，返回「文件:行号: 内容」 | read |
| `todo` | 维护任务清单（每次传完整清单，同一时间只有一项进行中） | read |
| `write_file` | 新建或整体覆盖文件；写前拍快照供 /undo | edit |
| `edit_file` | 精确替换：`old_string` 必须恰好出现一次（或 `replace_all`）；写前拍快照 | edit |
| `bash` | 在工作目录跑命令，有超时，输出过长截断，超时 / 中断杀整棵进程树 | exec |
| `web_fetch` | 读网页（http/https），转纯文本 | net |

所有路径经 `tools/paths.py` 解析：相对路径按工作目录算，解析后（含符号链接）必须仍在工作目录内。

## 5. 权限

| 模式 | read | edit | exec | net |
|---|---|---|---|---|
| `ask`（默认） | 直接执行 | 问 | 问 | 问 |
| `accept-edits` | 直接执行 | 直接执行 | 问 | 问 |
| `plan` | 直接执行 | 拒绝 | 拒绝 | 问 |
| `auto` | 直接执行 | 直接执行 | 直接执行 | 直接执行（只用于 CI、一次性沙箱；路径越界仍被拦） |

net 在 plan 模式下也问：读网页不改本地，但模型可能把代码内容拼进网址带出去。

确认时可选「这次允许」「本会话一直允许这个工具」「拒绝」。拒绝时工具不执行，告诉模型「用户拒绝了」，由它换路子。

## 6. 阶段

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| 1 核心 | 循环 + 流式；6 个工具；权限三模式；`HENG.md` 项目记忆；会话保存与 `--resume`；基础斜杠命令；`-p` 非交互 | 能完成一个真实的「读代码 → 改代码 → 跑测试修到通过」 |
| 2 生产力 | 技能（`.heng-agent/skills/*/SKILL.md` 按需加载）、自定义斜杠命令、上下文自动压缩、工具前后钩子、费用统计 | 日常用起来接近 Claude Code |
| 3 进阶 | 子智能体、MCP 客户端、计划模式增强（0.4：exit_plan_mode 交计划 → 用户选按哪种模式执行） | 能处理多步骤大任务 |

### 6.1 健壮性（第一阶段补齐，2026-10-26）

| 机制 | 做法 |
|---|---|
| 自动重试 | 429 / 408 / 5xx / 529、Anthropic 流里的 overloaded / rate_limit 错误、远程连接失败与读超时：指数退避 1/2/4/8 秒，有 `Retry-After` 就听它的，最多 4 次。**已经吐出文字后不重试**（屏幕上的半段回复与重新生成的对不上）。本机服务连不上不重试（多半是没启动） |
| 上下文压缩 | 上一次请求的输入 token 超过配置档 `context_window` 的 80% 时，下一轮前先压缩：旧历史渲染成纯文本（工具输出截断）交给模型总结，替换成「摘要」消息；末尾是工具结果时，带工具调用的助手消息与结果成对保留，否则工具结果会引用不存在的调用。`/compact` 手动触发 |
| 停掉命令 | 超时与 Ctrl+C 都按 PID 杀整棵进程树（Windows `taskkill /T`，其他系统进程组）。只杀 bash 时孙进程会继续跑，而且握着输出管道让超时失效 |
| Markdown | 文字按段用 rich `Live` 流式渲染 Markdown；工具调用、结束、提示等事件到来时固定当前段 |

## 7. 测试

- `tests/fake_model.py`：脚本化的假模型，实现与真实客户端相同的接口，按预设脚本吐出文字与工具调用。
  循环、权限、工具的测试都用它，不花 API 费用、结果可复现。
- 模型客户端的 SSE 解析用 `httpx.MockTransport` 喂录好的事件流测试，不连网。
- 端到端（连真实模型）手动验证，结果记在第 8 节。

## 8. 真实模型验证（2026-10-26，DeepSeek deepseek-v4-pro）

沙箱项目：购物车模块藏两个 bug（会员折扣返回了减免额而不是折后价、包邮门槛少了等号），3 个单元测试全失败。
任务只说「测试跑不过，修好并验证，不要改测试文件」，不提示 bug 在哪。

| 场景 | 结果 |
|---|---|
| Anthropic 协议（`--provider deepseek`），`auto` 模式 | 13.6 秒：跑测试 → 读源码与测试 → 改两处 → 重跑通过 → 报告；独立复核：测试通过、只改 `cart.py` 2 行、测试文件未动 |
| OpenAI 协议（DeepSeek 的 OpenAI 兼容地址），`auto` 模式 | 14.3 秒，同样修好并验证（换了一种等价的改法） |
| 默认权限的 `-p`（改文件被自动拒绝） | 文件未被修改；模型没有原样重试，而是说明发现与拟改方案并询问用户 |
| 密钥落盘检查 | 会话文件与两个仓库里都搜不到密钥 |

修正：模型习惯在命令前 `cd 绝对路径`，系统提示词加了一句「命令已在工作目录执行、路径用相对路径」，之后的运行里不再出现。

**P1 三步任务（2026-10-26）**：「修 bug + 新增 apply_coupon + 补测试」，34 秒完成，4 个测试通过，补的测试主动覆盖了边界。
但模型**没有调用 todo 工具**（提示词写了「三步以上先列清单」）。待更多真实任务观察后再决定是否加强提示。

**第二阶段（2026-10-26）**：技能、自定义命令、钩子。实测（DeepSeek，沙箱项目配了 test-style 技能、/addtest 命令、
改文件后跑 py_compile 的项目钩子）：

| 场景 | 结果 |
|---|---|
| `-p "/addtest shipping"`（修复前） | **发现 bug**：Git Bash 把以 `/` 开头的参数当路径转成 `D:/software/dev/Git/addtest`，命令没展开，模型去 Git 安装目录里找了一圈（14 次工具调用）才弄明白 |
| 修复：`cli.undo_msys_pathconv` | 在 Git Bash（MSYSTEM）里、以 Git 安装目录开头、剩下的确实是已定义命令时还原成 `/命令` |
| `-p "/addtest apply_member_discount"`（修复后） | 6 次工具调用：读源码 → **主动读 test-style 技能** → 补测试（每个都有中文 docstring、测了边界） → 跑测试通过 |
| 项目钩子 | 每次改文件后都跑了 py_compile，「语法检查通过」附进了工具结果 |

**第三阶段（2026-10-26）**：子智能体、图片输入、MCP 客户端。

| 设计 | 理由 |
|---|---|
| 子智能体只读（read_file / glob / grep，plan 权限，不能再派子智能体） | 并行的子智能体若能改文件、跑命令，确认对话会互相打架、并发写同一个文件会冲突；只读就能安全并发 |
| 同一轮全是 task 时用线程池并行（最多 4 个），结果按原顺序交回；用量用回调加锁汇总 | 用量若存在工具对象上，并行时会互相覆盖 |
| 图片：`@图片` → Anthropic 图片块；OpenAI 协议转 `image_url` 数据 URL；压缩时记为「用户附图」占位 | 终端里没法直接粘图；base64 不能塞进摘要 |
| MCP：stdio、逐行 JSON-RPC，握手 → tools/list（分页）→ tools/call；工具名 `mcp__服务__工具`，权限类别 mcp 除 auto 外都问 | 外部工具做什么不可知 |
| 项目 MCP 服务与钩子共用信任记录（`core/trust.py`，按配置指纹） | 「启动一个程序」与钩子风险相同 |

实现中自查出的 bug：MCPManager 启动失败时用 `"client" in locals()` 判断要不要关连接——循环里它可能指向**上一个已启动成功的
服务**，会把好的服务误关掉。改成每轮重置，并加了回归测试（坏服务排在好服务后面，好服务仍在运行）。

实测（DeepSeek）：同一轮派出两个子智能体并行调研 cart.py 的包邮与折扣规则，结论与代码一致；调用 MCP 工具
`mcp__calc__add` 算出 100；48 秒完成。**注意**：子智能体的事件不显示在界面上，只显示主智能体的 task 调用与结论。
